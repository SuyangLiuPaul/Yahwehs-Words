# Reading plans (back 2026-10-15)

Words only. Sword is a study workbench, not a daily-reading app, and has no plans.

## What it is
Six plans, picked on `/reading-plan` (home card "Reading plan", Settings → Home sections):
`bible-1y` (whole Bible in a year, Bible order), `bible-1y-ot-nt` (OT and NT together; NT ends day 260),
`mcheyne` (M'Cheyne 1842, four readings a day), `nt-90`, `gospels-30`, `psalms-proverbs-31`.
A reader starts a plan on any date; day n is n-1 days after the start date. Days can be ticked in any order.

## Where things are
- Data: `assets/reading_plans.json`, GENERATED by `tools/build_reading_plans.py` (never edit by hand;
  `--check` is a test). Derived plans are cut into whole chapters balanced by verse count from
  `assets/kjv.json`; each chapter once, in order. No "chronological" plan: nothing in the repo to verify one against.
- M'Cheyne: `tools/data/mcheyne_1842.json` (public domain). Extracted from Ben Edgington's transcription
  of the 1842 calendar (edginet.org PDF, via pdftotext -bbox), checked day by day against Will Norris's WordPress
  plugin (cchmb/mcheyne-reading-plan) and jpillion/daily-readings: all 365 days agree, including the 37
  verse windows (Psalm 119 in seven parts, Exodus 11:1-12:21 …). One other copy (scottdc92/christian_json)
  disagrees from August 4 on and was NOT used. The calendar has no February 29.
- Code: `lib/services/reading_plan_service.dart` (plans, progress, merge, status), `lib/pages/reading_plan_page.dart`,
  home card `_ReadingPlanCard` in `dashboard_page.dart`. Strings: `readingPlan_*` in `ui_strings.dart`.
- Tests: `test/reading_plans_test.dart` (26).

## Rules that came from the first version's failure (removed v1.2.69, hotfix v1.3.45)
- Progress is ONE key with no dot, `readingPlan`, a JSON blob, profile-scoped. Dotted `plan.*` keys are rejected
  by Firebase RTDB and once broke every sync write. A test forbids `'plan.` in the sync layers.
- Sync merges by `mergeReadingPlanBlobs`: same plan + same start → union of days read; otherwise the newer
  choice wins; a stopped plan is a timestamped blob so a stop is not undone by a stale plan on another device.
- Day arithmetic uses UTC dates (a daylight-saving change must not skip or repeat a day).
- The old `plan.*` prefs of long-time readers are left alone; nothing reads or deletes them.
- Plan data is in the web offline pack list (`offline_pack_service.dart`).

## Not done
- Reminder notification for the day's reading (the scheduler has categories; a plan reminder would be one more).
- Per-day "catch up" shortcut beyond the "continue from day N" line.
- Not merged, not released, version unchanged (1.7.25).


## The reader opened from a plan (2026-10-16)

Tapping a passage chip opens the reader as a `ReadingSession`
(`reading_plan_service.dart`): the day's chapters, in the plan's order,
and nothing else. Genesis 1-3 is three pages.

- the pager (`_paneChapters` in `bible_reading_pane.dart`) pages only
  those chapters; swipe, the bottom bar's arrows and the keyboard stop
  at the ends, and the book chip no longer opens the book picker;
- the top-left button is a back arrow to the plan (not Home), and the
  header's search is hidden;
- a strip over the bottom bar shows "Chapter n of N" with a progress
  bar; on the last chapter it offers "Mark today as read", which sets
  the day done and returns to the plan;
- a day with several passages (M'Cheyne) is one session across all of
  them. A passage that starts inside a chapter still reads as whole
  chapters; the reader opens on its first verse;
- if the reader ends up on a chapter outside the day (a jump from
  elsewhere) the session quietly steps aside and the ordinary reader
  pager takes over.

The Home page's Quick links also carry a "Reading plans" tile.


## Several plans at once (2026-10-16)

What other Bible apps do, and what was taken from them (Bible Gateway:
own start date, pause and resume, reminders per plan; Logos and A Lamp
Unto: catching up without guilt — slide the schedule, or leave the
missed days behind; MyBible: a start date per plan, several plans
together; Bible Box: finished plans kept, not lost):

- **Several plans run side by side** (up to `kMaxReadingPlans` = 8). Each
  is a `ReadingPlanProgress` with its own id, so the same plan can run
  twice on different dates. All are stored in ONE blob under the one
  undotted key (`ReadingPlansDoc`, format v2). The 1.7.26/27 single-plan
  blob and its "stopped" form still parse.
- **Start date** is chosen when a plan is started (today, tomorrow, any
  date) and can be moved later. Days read are plan day numbers, not
  dates, so moving it never un-reads anything.
- **Pause / resume**: the plan's calendar stands still, no reminders;
  resuming adds the paused days to the start date, so nothing is behind.
- **Catch up**, two ways, never silently marking anything read:
  *pick up where I left off* slides the schedule so the first unread day
  is today; *skip the missed days* moves them to `skipped`, so they stop
  counting as behind.
- **Reminders are per plan**: on/off, its own time (else the Reading plan
  category's), and the reader's own words as the notification title
  (else "<plan> · Day n of N"). Several plans book separately, ids
  1100 + 14 × slot + day. Turning a plan's reminder on also turns the
  category on; if the notification master switch is off the sheet says so
  and offers Settings. On the web there is one time per category, so the
  per-plan time is hidden and everything due is sent as one notification.
- **Home card**: absent until a plan has been started (the Reading plans
  tile in Quick links is the way in); then one row per plan.
- **Sync**: merged per plan id — the days read or skipped on either
  device are kept, every other field follows the newer edit, a removed
  plan stays removed (tombstone, forgotten after 90 days), and a
  1.7.26/27 "stop" still beats an older plan (`clearedMs`).

Not done, on purpose: choosing weekdays a plan runs on (the Reading plan
reminder category already has weekdays for reminders), streak counters,
sharing a plan with friends.


## Complete plans (2026-10-16)

What was still missing after "several at once", and is now there:

- **"Read" means read.** Opening a day from a plan, a chapter counts when
  the reader has scrolled to its END (its footer is on screen; a chapter
  that fits one screen is all in view). Chapters are remembered per day
  (`readChapters`) across closing the reader; when every chapter of the
  day has been, the day is read, dated (`doneOn`) and a toast says so.
  Making up an earlier day works the same way (open it from "All days").
  Ticking a day by hand still works, for reading done elsewhere.
  Only the chapter on screen counts: a swipe settling can still fire the
  old page's listener, so its end is never credited to the next chapter.
- **Your own plan.** Any books, in a number of days or by a finish date;
  each day carries about the same number of verses. The schedule is cut
  on the device from `assets/chapter_verses.json` by the same algorithm as
  `tools/build_reading_plans.py`; a test proves the whole Bible in 365 days
  is exactly the bundled plan, and that every chapter comes up once.
  Only the books and day count are stored (`CustomPlanSpec`).
- **Days off** (weekdays the plan does not run on): a day off does not
  advance the plan and is not reminded. Changing them keeps today on the
  same plan day. Pause/resume and catch-up are day-off aware
  (`startForDayOn`).
- **Streak**: consecutive days with any reading, across all plans
  (yesterday still counts until a whole day is missed), longest run, days
  read. Dates are kept per day read; sync keeps the earliest.
- **Bulk catch-up**: "mark the N earlier days as read" for what was read
  elsewhere, dated on the days they fell so a streak is not invented.
- **Read it again** on a finished plan; **share my progress** (the OS
  share sheet, or a copy to the clipboard where there is none); every
  day in "All days" shows its date and an "open this day" button; each
  plan shows when it will finish.
- **The calendar moves**: `startDayWatch()` re-reads "today" at midnight
  and when the app returns to the foreground, and re-books reminders.

Not done, on purpose: chronological / thematic orders (no verified
public-domain ordering is in this repository to check one against),
audio, reading with friends. Everything in the plan list and a reader's
own plan is unaffected by the Bible version in use.
